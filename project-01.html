EKON.

01Project Overview

What is EKON?

EKON (एक-ON, meaning "one" in Hindi) is a mobile application that uses a multi-model ML pipeline to identify individual birds — not just species — through photographs. The pilot species is the Common Myna, one of India's most widespread urban birds.

The project was designed as my B.Des capstone thesis at Anant National University, sitting at the intersection of conservation technology, citizen science, and human-centred design.

The Gap
Existing tools (eBird, Merlin, iNaturalist) identify species but cannot track individual birds across sightings — critical data for understanding territory, migration, and population health.
The Opportunity
Build a non-invasive alternative to physical tagging and ringing that is accessible to both citizen scientists and professional researchers — at zero cost per bird.
02Problem Statement

We count birds. We don't know them.

Traditional individual identification methods — leg rings, wing tags, GPS transmitters — cost Rs. 4-5 lakhs per bird, require handling, and are impossible to deploy at scale with volunteer networks.

Meanwhile, millions of citizen science observations are collected every year with zero capacity to answer the most ecologically meaningful question: is this the same bird I saw last week?

How Might We
"How might we enable citizen scientists and researchers to identify individual birds non-invasively, using only a photograph taken with a smartphone?"
03Research

Understanding the users and the field.

I conducted 12 semi-structured interviews across three user groups: casual birders, active citizen scientists, and professional field researchers. I also reviewed 30+ academic papers on bird biometrics, wildlife tracking, and ML-based individual recognition.

Insight 01 · Trust
Users want to understand why two photos are matched. A black-box result felt untrustworthy — especially for researchers who need to cite data.
Insight 02 · Non-invasive
Every participant — including those who currently use physical tags — said they would prefer a non-invasive method if it were equally reliable.
Insight 03 · Scope
Attempting many species at once reduces reliability. One species done well was preferred over five done poorly. Common Myna was the unanimous pilot choice.
04Define

Four users. Four modes. One app.

Research revealed four meaningfully different user types with different goals, contexts, and expectations. Rather than one generic flow, I designed four modes within a single app — each with its own information architecture and interaction patterns.

05Solution

A four-stage ML pipeline, not a single model.

Individual recognition is not one problem. It requires species confirmation, feature detection, fingerprint extraction, and identity matching — each a separate model optimised for its task.

Stage 01
BirdNET
Species confirmation. Rejects non-Myna photos before processing begins.
->
Stage 02
YOLO v10
Feature detection. Locates eye, beak, legs, and plumage patches.
->
Stage 03
ResNet-50
Feature embedding. Extracts a unique 128-dimension fingerprint vector.
->
Stage 04
FAISS
Identity matching. Matches against database or assigns new ID.

Confidence threshold design: matches above 80% auto-save. Below 80%, the app surfaces which features were used (eye weight 40%, plumage 35%, legs 20%, beak 5%) and asks the user to confirm — building trust through transparency.

06Design

Designing for trust, not just usability.

The core design challenge wasn't the UI — it was making ML decisions feel trustworthy. Every match shows the user which features were used and with what weight. The system acts first; the user corrects only when needed.

01
ML-first, human-corrected
The system assigns identities automatically. Users only intervene when confidence drops below 80% — reducing cognitive load while maintaining accuracy.
02
Transparent reasoning
Every match surfaces the features used and their weights — eye, plumage, legs, beak. Users see the model's logic, not just its conclusion.
03
Progressive disclosure
Casual users see a clean, simple interface. Researchers unlock detailed metadata, export tools, and batch workflows — same app, different depth.
04
Designed for every state
Empty collection, low-quality rejection, species mismatch, offline sync, batch upload — every edge case has an intentional, non-blocking resolution.
